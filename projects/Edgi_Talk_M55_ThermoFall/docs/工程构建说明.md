# Edgi_Talk_M55_ThermoFall 构建与烧录说明

实验 4 工程：M55 核单工程内融合 AHT20 温湿度 + LSM6DS3 摔倒检测，
LVGL 双页面（Thermo / FallCheck）触摸切换，LED 按当前页面仲裁，KEY 按页面执行暂停/静音，
FallCheck 页面确认 FALL 且未静音时播放 ROMFS 中的 `/webnet/beep.wav`。

RT-Thread ENV 工具的通用用法见 [`../../exp-docs/RT-Thread-ENV使用说明.md`](../../exp-docs/RT-Thread-ENV使用说明.md)，
本文件只写本工程相关的部分。

---

## 1. 前置条件（只需做一次）

### 1.1 建立目录联接（junction）

工程依赖四个 junction，它们被 `.gitignore` 忽略，**每个工程都要单独建**：

```bat
cd Edgi_Talk_M55_ThermoFall
mklinks.bat
```

等价于：

| 联接 | 指向 |
| --- | --- |
| `rt-thread` | `sdk-bsp-psoc_e84-edgi-talk/rt-thread` |
| `libraries` | `sdk-bsp-psoc_e84-edgi-talk/libraries` |
| `libs` | `sdk-bsp-psoc_e84-edgi-talk/projects/libs` |
| `tools` | `sdk-bsp-psoc_e84-edgi-talk/tools` |

没建联接会直接报 `Cannot found RT-Thread root directory, please check RTT_ROOT`。

### 1.2 进入 RT-Thread ENV

```bat
cmd /c "call E:\sdk\rtthread\env-windows-v2.0.0\env-windows\tools\bin\env-init.bat && pwsh.exe"
```

这一步会设置 `RTT_EXEC_PATH`（ENV 自带 arm gcc 10.3.1）并激活 Python 3.11.9 venv
（含 scons / menuconfig / pkgs）。

> **不要修改 `rtconfig.py` 的 `EXEC_PATH`。** 它里写死的
> `C:\RT-ThreadStudio\...\13.3\bin` 在本机不存在，但 `rtconfig.py:28-29` 会用
> `RTT_EXEC_PATH` 覆盖它，所以在 ENV shell 里构建就是好的，换到装�� RT-Thread Studio
> 的机器上也能直接用。

### 1.3 不需要 `pkgs --update`

`packages/` 下的 `aht10-latest`、`lsm6ds3tr`、`wavplayer-latest`、`cpu_usage-latest`
已全部内置在仓库里，离线即可构建。

## 2. 构建

```bat
cd Edgi_Talk_M55_ThermoFall
scons -j12
```

产物在**工程根目录**：

| 文件 | 来源 |
| --- | --- |
| `rtthread.elf` | `SConstruct` 的 `TARGET = 'rtthread.' + rtconfig.TARGET_EXT` |
| `rtthread.hex` | `rtconfig.py` 的 `POST_ACTION`（objcopy -O ihex） |
| `rtthread.map` | `LFLAGS` 里的 `-Map=rtthread.map` |

清理：`scons -c`，或直接删 `build/` 与 `.sconsign.dblite`。

### 关于 `Debug/rtthread.elf`

指南里说下载目标统一为 `Debug/rtthread.elf`，本工程的三个 `.launch` 也指向它。
但 **scons 不产出 `Debug/`** —— 那个目录由 RT-Thread Studio 的 Eclipse 托管构建
（`makefile.targets` + 自动生成的 `Debug/makefile`）产生，且被 gitignore。

所以：
- 用 scons → 产物在工程根（`start.py` 的 `rglob("rt*thread*.hex")` 取的就是它）
- 用 RT-Studio → 先在 Studio 里跑一次构建，`Debug/rtthread.elf` 才会出现

**不要**为了凑 `Debug/` 而在 `POST_ACTION` 里加拷贝步骤——那会让 `start.py`
的 hex glob 拿到两个候选，而它只取 `[0]`。

## 3. 配置

**`rtconfig.h` 是权威，`.config` 是派生物。** 改完 `rtconfig.h` 后同步：

```bat
scons --genconfig
```

**不要跑 `menuconfig`**，原因见 ENV 说明文档第 5.1 节。最要紧的一条：
`PKG_AHT10_I2C_BUS_NAME` 在 Kconfig 里位于 `if PKG_USING_AHT10_SAMPLE`（默认 `n`）之下，
menuconfig 会把它**静默丢掉**，导致 `main.c` 编译失败。
`main.c` 里已加了 `#ifndef PKG_AHT10_I2C_BUS_NAME` 兜底，但 Kconfig 层面仍然拿不回来。

关键配置项：

| 符号 | 值 | 作用 |
| --- | --- | --- |
| `BSP_USING_SOFT_I2C2` / SCL / SDA | y / 75 / 74 | AHT20 所在的软件 I2C2 |
| `BSP_USING_SOFT_I2C1` / SCL / SDA | y / 105 / 106 | **必须保留**：触摸屏 ST7102 硬编码用 `i2c1`（`drv_touch.c:417`） |
| `BSP_USING_HW_I2C0` | y | LSM6DS3 与 ES8388 共用 |
| `PKG_AHT10_I2C_BUS_NAME` | `"i2c2"` | AHT20 挂载总线 |
| `PKG_WP_PLAY_DEVICE` | `"sound0"` | wavplayer 播放设备（由 `drv_i2s.c` 注册） |
| `RT_USING_DFS_ROMFS` + `RT_USING_LIBC` | y | ROMFS 与 `fopen` |
| `BSP_USING_LSM6DS3` | y | 摔倒检测包编译开关 |
| `LVGL_USING_DEMOS` | 关闭 | 保留 `/* #undef */` |

## 4. 烧录与串口

串口：UART2（波特率看 `RT_CONSOLE_DEVICE_NAME` / BSP 默认配置）。

一键编译 + 烧录（需 `pydantic`、`pydantic-cli`）：

```bat
python ..\start.py <OpenOCD安装目录> --projectMainDir .
```

`start.py` 内部就是 `scons -jN` + OpenOCD `flash write_image erase`。
因为它是 scons 的子进程，只要在 ENV shell 里运行就能继承 `RTT_EXEC_PATH`。

## 5. 上板验收清单（对应指南「验证要点」）

1. **触摸按钮**能切换 Thermo / FallCheck 两个页面。
2. **Thermo 页面**显示温度、湿度、舒适度等级（COMFORT / WARM / ALARM / DRY-COOL）。
   串口出现 `[ThermoFall] AHT20 ready on i2c2`；若显示 `AHT20 OFFLINE / RETRY`
   说明 `i2c2` 总线没起来。
3. **FallCheck 页面**显示 acc（mg）、gyr（dps）与 IDLE / MOVING / FALL 状态。
   启动瞬间显示 `LSM6DS3 STARTING` 是正常的——`g_fallcheck_shared` 位于
   `.m33_m55_shared_hyperram`（NOLOAD 区），C 初值会被丢弃，由传感器线程重新赋初值。
4. **LED 只跟随当前页面**：切到 Thermo 就看舒适度灯，切到 FallCheck 就看摔倒状态灯。
   后台 Fall 任务即使检测到 FALL，只要页面还在 Thermo，就不抢灯、不响。
5. **KEY**：Thermo 页面下暂停/恢复采样（`PAUSED BY KEY`），FallCheck 页面下切换静音
   （`FALL DETECTED - MUTED`）。
6. **报警音**：FallCheck 页面 + FALL 状态 + 未静音时每 2500 ms 播放一次 `beep.wav`。
   串口出现 `[ThermoFall] ROMFS beep ready` 表示 ROMFS 挂载成功；
   若 `sound0` 找不到，`wavplayer_play()` 返回非 0，日志会周期性报失败。

## 6. 已知坑

1. **`board/SConscript` 不要加回 `BUILD_KIT_PROCE84_EVK_M55`**：它唯一的作用是让
   `libs/.../ns_start_pse84.c` 定义一个空壳 `__set_MSPLIM`，而当前 CMSIS
   （`Core/Include/m-profile/cmsis_gcc_m.h:679`）已提供该函数，重复定义直接编译失败。
   另外注意 `building.py:642` 会把 group 的 `CPPDEFINES` **追加到全局 Env**，
   所以这个宏会从 `board` 泄漏到 `libs`，影响面比看起来大。
2. **`packages/lsm6ds3tr/SConscript` 里的 `FLT_EVAL_METHOD=0` 不能删**：ST 的寄存器层
   `lsm6ds3tr-c_reg.h` 用 `float_t`，而本工具链 newlib 4.1.0 的 `math.h` 在
   `__FLT_EVAL_METHOD__ == 16`（既非 0/1/2）时不 typedef `float_t`，改为假定由 `config.h`
   提供 —— 结果就是 `unknown type name 'float_t'`。显式定义 `FLT_EVAL_METHOD=0`
   （无扩展精度，符合 Cortex-M55 硬浮点实际行为）后 newlib 才会给出
   `typedef float float_t`。换用更新的工具链（如 gcc 13.x 的 newlib）可能不再需要。
3. **首次构建较慢**：LVGL 的 `.o` 写进共享的 `libraries/components/lvgl_9.2.0/`，
   本工程 `rtconfig.h` 与 `Edgi_Talk_M55_LVGL` 不同（无 `RT_USING_CACHE`、无 demos、
   显示缓冲行数不同），会触发 LVGL 全量重编；`romfs.c`（916 KB C 数组）在 `-O0` 下也慢。
4. **`RT_USING_CACHE` / `RT_USING_CPLUSPLUS` 保持缺失**（与参考实现一致）。
   补上只会再触发一次 LVGL 全量重编，本工程没有 C++ 代码，无收益。
5. **`msh_exec_stub.c` 不能删**：`DFS_USING_WORKDIR` 打开时 `msh_file.c` 会引用
   `msh_exec_script`，缺少它是**链接错误**，容易被误判成 DFS 配置问题。
6. **LSM6DS3 线程由 `INIT_APP_EXPORT` 自动创建**（`fall_sns`，2048 / prio 20），
   `main()` 里不要再创建一遍。它先于 `main()` 运行，别在 `main()` 里加对它的启动依赖。
